# 期货与套利

**定义**：在期货（股指/商品）上交易的范式，分两类——**套利**（市场中性，赚价差回归，如跨期）与**方向性趋势**（用 [[动量与趋势]] 信号做多空）。区别于股票策略：带保证金、双向、平今仓手续费高。

## 观察
- **套利 vs 趋势**：跨期套利（1294c538）夏普最高（3.53）且与股票方向性策略低相关，是组合分散的好补充；方向性期货趋势（ec720559/10a3c43d）收益温和、依赖追踪止损控回撤。
- 期货策略普遍回撤可控（6–16%），但受保证金与平今仓成本约束。
- **股指期货对冲的 basis 风险主导——对冲工具须匹配 alpha universe 的规模**（epoch2 jul12 Arc-4，[[jul12-023]]）：IC（中证500，中盘）对中证**微盘**多头是**不充分对冲**。一个「微盘最小10只多头 − IC 空头@1.2×」的市场中性组合，在 2022-23 熊市 TRAIN 上把裸微盘回撤从 25.4% 腰斩到 12.3%、夏普 2.64 **过门槛**——但在 2024 微盘专属崩盘（雪球/DMA/量化去杠杆）里**灾难反转**：微盘跌幅远超中证500，IC 空头没保护，maxdd 冲到 **41.6%**、VAL 年化 −11%。TRAIN 的过门槛是 IC/微盘熊市**同跌**的 regime-specific 巧合，2024 同向性破裂即失效。→ **对冲工具须匹配 alpha universe 的规模**；IM（中证1000）basis 更近微盘但 2022-07 才上市、覆盖不了 2022 TRAIN 起点。⚠ 且期货腿滑点/手续费/基差/换月拖累在本纪元零滑点+股票费率下**未计入**，objective 偏乐观。
- **【可复用检测法】「事件驱动 / 数据套利」类策略里，带嵌入式信号载荷的那一支要先问「这份策略自足吗」——而这与「有没有前视泄漏」是两个不同的问题，必须分开裁决**（study [[套利]] q-payload 零回测载荷审计，TRAIN 2022-2023 冻结零滑点 ⚠）：该家族 base 用 **`EMBEDDED_SIGNAL_JSON`**（**L23**，单行 **25,672 B ≈ 25.1 KB**，占全文件 32,419 B 的 **79%**）承载 **32 个 NBS 工业企业利润事件**，代码在发布 +4 交易日买入、+24 交易日清仓。**审计的两级结论必须按这个顺序说**：**(一) 免责事实（穷举验证，非印象）** —— 载荷的 **23 个 JSON key** 全部枚举过（事件级 `release_date / buy_offset / sell_offset / hold_days / etfs[] / signals[] / candidate_signals[] / selection_rule / source_urls[]`，信号级 `etf / industry / profit_yoy / profit_yoy_delta / url`，84 个信号对象），**没有任何价格、收益、盈亏、已实现方向、意外符号或结果字段**；且**唯一的行情调用是干净的** —— `get_price(...)` 的返回值**只被消费为 `len(prices) - 1`**（一个交易日计数器），收盘价从未被读取 ⇒ **这不是「把结果嵌进来了」，载荷是「日期 + 标的」。** **(二) 但它仍然不合格，理由是另一条** —— 它是一份**回溯日志而不是发布日历**：公开发布日历一年约 **11 个** NBS 日期、**包含未来日期**、且**不预挂标的**；这份文件是 32 事件 / 约 54 个月、**条条已附解出的标的、零条前瞻记录**（无一晚于自身 `updated_at`），**2022 只有 4 条**（Feb/Mar/May/Jun/Jul/Aug/Sep/Dec 全缺）⇒ 策略在基准 −21.6% 的那年大部分时间**空仓**。而**代码对事件列表不施加任何筛选、逐条无条件交易**（`signals` / `profit_yoy` / `selection_rule` 这些字段**从未被代码读取**，32 条中 17 条有 ≥2 个候选 ⇒ 离线确实做过 top-1 取舍），做出取舍的生成器 `nbs_sync_strategy_to_jq.py` **只在注释里被点名、不在仓库里** ⇒ **回测无法重新推导、也无法审计这一步**。实测层面这条是决定性的：**12 条事件落在 TRAIN、11 条触发，与回测实测的 11 笔逐笔吻合 ⇒ 载荷 100% 决定交易簿**，而那本账的 **19.23% 年化**与**异常低的 13.47% 波动**（89.85% 特质）**都是载荷稀疏性的后果**。→ **检测法（对本仓库所有「事件驱动 / 数据套利 / 打分表外置」策略通用，四步）**：① 枚举载荷全部 key，确认有无结果类字段（**这一步过了不等于合格**）；② 数「前瞻条目」——**一份真日历必然含未来日期**，零前瞻 = 回溯日志签名；③ 看代码**是否对列表施加任何筛选**——若不筛选，则选择在离线端、交易簿由载荷唯一决定，可用「载荷内落窗事件数 vs 实测笔数」一比即知（此例 11/11）；④ **逐条核 `source_urls` 的发表日期与该条事件自身的日期**——此例前 8 个事件的 URL **全部发表于 2023-02-03**、文章 ID 连号（档案列举式特征）、比名义发布日晚 3–15 个月，**触及 11 个 TRAIN 交易中的 5 个**。**第 ④ 步的结论只能写成这个形状**：「**N 个交易由发表时间晚于该笔交易的来源所记录的数值触发；这确立了该字段不是 point-in-time，但它本身并不表明任何符号或选择发生过改变**」——⚠ **只标不裁决**，要裁决需发布日原始印数（NBS 会按同口径修订 工业企业利润 YoY），本仓库没有。→ **可复用的判词形状**：这类策略的正确结论往往**不是**「有前视泄漏」（那是一个更强、通常证不了的指控），而是「**它不是自足的，所以那个回测数字衡量载荷作者的程度，与它衡量一条规则的程度一样多**」；相应地，**在生成器被取回或规则被搬进代码之前，它是不可评价、因而也不可优化的** —— 对它做参数扫描只会过拟合载荷的稀疏性。confidence med（静态审计，非实验）；⚠ **flagged-not-adjudicated**。溯源 [[套利]] q-payload。
- **一个「不设任何成本」的策略反而是本项目成本口径最干净的一支**（study [[套利]] baseline）：该 base 全文**无 `set_slippage` / `set_commission` / `set_order_cost`** ⇒ 冻结 harness 的 OVERRIDE **无争用**，是本批次**首个**不受项目级 `set_order_cost` 歧义影响的家族（对比 [[趋势技术]]：源码 2.5bp/12.5bp vs harness 3bp/13bp，缺口已被界定为 ≈0.15pp/年）。配合 `turnover 0.02044` / 两年仅 **11 笔** ⇒ 滑点还原仅约 **0.5–1.0pp/年**，对 **17.77pp** 的落闸缺口无关紧要 ⇒ **照实报数、不挂笼统 ⚠零滑点高估**。→ 可复用读法：**低频事件驱动策略的真实性风险几乎不在成交假设上**，把审计预算投到信号来源与 universe 构建那一侧回报更高。溯源 [[套利]]。
