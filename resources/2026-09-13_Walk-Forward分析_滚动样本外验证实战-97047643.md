# Walk-Forward分析：滚动样本外验证实战

上一篇讲过用随机模拟检验过拟合，这篇补上另一半：**参数是怎么被选出来的，就该用与选择过程一致的方式去验证**。固定的一次性样本内外切分有盲区，Walk-Forward（滚动前推）分析是更接近真实使用场景的验证框架。通用教学内容，不构成投资建议。

## 一、固定切分的盲区

常见的验证流程：用2015~2021年优化参数，2022~2024年做样本外检验。这个流程有两个盲区：

1. **样本外窗口只有一段**：2022~2024恰逢某种市场状态，结果好坏很大程度取决于这段行情"运气"；
2. **没有模拟"参数会过期"**：真实使用中，参数是基于历史数据定期重估的，每次重估后的参数都在变。固定切分只检验了"一组参数"的样本外表现，没检验"参数选择流程本身"是否稳定。

## 二、Walk-Forward的标准流程

Walk-Forward把历史按时间切成连续的窗口，逐段滚动：

```
窗口1: [2015-2017优化] → [2018验证]
窗口2: [2016-2018优化] → [2019验证]
窗口3: [2017-2019优化] → [2020验证]
......依次滚动到数据末端
```

每个窗口：在训练段（IS）网格搜索出最优参数，然后**冻结参数**在紧随其后的测试段（OOS）运行。把所有OOS段的收益拼接起来，得到"滚动样本外净值曲线"——这条曲线模拟的是"你当年真的在用这套参数"的累积结果。

```python
# 骨架: 逐窗口优化+验证
def walk_forward(data, is_years=3, oos_days=244, param_grid):
    oos_nav = pd.Series(dtype=float)
    for start in range(0, len(data) - is_years*244 - oos_days, oos_days):
        is_end = start + is_years * 244
        train = data.iloc[start:is_end]
        test = data.iloc[is_end:is_end + oos_days]
        best_param = grid_search(train, param_grid)   # IS段选参
        oos_ret = run_strategy(test, best_param)      # OOS段固定参数运行
        oos_nav = pd.concat([oos_nav, oos_ret])
    return oos_nav.cumprod()
```

## 三、评价Walk-Forward结果的三个指标

1. **OOS年化与IS年化的比值（WF效率）**：滚动样本外年化 ÷ 各窗口IS年化的平均。比值长期低于0.5，说明参数过拟合严重——每次选出的"最优参数"到样本外都大幅缩水；
2. **参数漂移图**：把每个窗口选出的最优参数画成时间序列。如果参数在区间内大幅跳动（这个月用20日线、下个月用55日线），说明最优点不稳定，策略逻辑可疑；
3. **OOS胜率**：所有OOS窗口中正收益窗口的占比。低于60%的策略，其实战持有体验会非常差。

## 四、两个必须避免的坑

**1. 窗口重叠泄漏**：OOS窗口和下一个IS窗口可以紧邻，但**不能重叠**——如果窗口2的训练段包含了窗口1的测试段，信息就泄漏了。滚动窗口（rolling）和锚定窗口（anchored，训练段起点固定、终点前推）都可以，重叠不行。

**2. 用WF结果再调参**：Walk-Forward跑完发现"IS三年、OOS一年"的组合效果最好，于是改成这个配置——恭喜，你把过拟合推进到了验证流程本身。WF框架的调参（窗口长度、搜索网格）应该用极少量、有先验理由的设置，跑完就固定。

## 五、进阶变体

- **Anchored Walk-Forward**：训练段起点固定在数据起点、终点不断前推。训练数据越滚越多，适合数据量少的场景；
- **多参数并行WF**：对多组候选策略各自跑WF，比较它们的OOS曲线稳定性——这是策略间比较最公平的方式；
- **加蒙特卡洛扰动**：在每个OOS段对成交顺序做随机重排，评估结果的置信区间。

WF的本质是把"******会周期性重估参数"这个动作在回测里如实重演。验证流程和真实使用方式一致，样本外结果才有意义。欢迎评论区交流你的WF参数设置。
