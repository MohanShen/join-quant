# 打板基础设施：涨停板识别框架

涨停识别框架：一次搞定首板到高度板 + 一字/T字/换手/炸板（附完整代码）
做打板策略的朋友都知道，涨停识别是第一步。但这一步坑不少：用错字段、漏掉停牌、炸板永远0、数板循环太慢……我之前也踩了一堆坑，后来整理了一套还算靠谱的框架，今天分享出来，希望能帮大家少走弯路。

一、为什么需要专门的涨停识别框架？
先看几个常见问题：

用 prev_close * 1.1 判断涨停，结果创业板20%、ST股5%全错；

停牌日打断连板，把二板算成了首板；

粗筛只筛收盘涨停，炸板股全被过滤，is_za 永远是0；

数板用双重循环，3000只股票跑5秒，回测慢得想砸电脑；

日期列处理不当，显示成 1970-01-01。

这些问题不解决，策略回测结果根本不可信。所以我花时间写了一个涨停识别框架，核心目标：一次获取数据，全部识别完成，向量化计算，零循环。

二、框架能识别什么？
数板
首板、二板、三板、四板、五板、六板

高度板（≥7板）

板型
一字板：open == high_limit 且 low == high_limit

T字板：open == high_limit 且 low &lt; high_limit

换手板：open &lt; high_limit 且 close == high_limit

炸板：high == high_limit 且 close &lt; high_limit

附带
停牌自动跳过（不打断连板）

日期自动修复（不再出现1970）

三、核心设计：一次获取，全部识别
传统做法是逐只股票查、重复请求、循环数板。我的做法是：

一次 get_price 拿到所有股票最近N天的数据，构建一个“涨停状态矩阵”，然后所有识别都基于这个矩阵做向量化计算。

python
matrix = get_price(
    stocks, end_date=date, count=10,
    fields=['open','close','high','low','high_limit','paused'],
    panel=False, fill_paused=False, skip_paused=False
)
拿到数据后，直接算出所有派生字段：

python
df['is_limit_up'] = (df['close'] == df['high_limit']) & (df['paused'] == 0)
df['is_yizi'] = df['is_limit_up'] & (df['open'] == df['high_limit']) & (df['low'] == df['high_limit'])
df['is_tzi'] = df['is_limit_up'] & (df['open'] == df['high_limit']) & (df['low'] &lt; df['high_limit'])
df['is_huanshou'] = df['is_limit_up'] & (df['open'] &lt; df['high_limit'])
df['is_za'] = (~df['is_limit_up']) & (df['high'] == df['high_limit']) & (df['paused'] == 0)
四、数板：cummin 向量化（50倍提速）
数板是连板数的统计。传统做法是双重循环：

python
for code, group in matrix.groupby('code'):
    for _, row in group.iterrows():
        if row['is_limit_up']: count += 1
        else: break
3000只×10天 = 30000次迭代，Python层慢得离谱。

我的做法是用 cummin：

python
df = df[df['paused'] == 0].sort_values(['code','date'], ascending=[True,False])
df['lim'] = df['is_limit_up'].astype(int)
df['streak'] = df.groupby('code')['lim'].cummin()
counts = df.groupby('code')['streak'].sum()
原理很简单：对于倒序排列的涨停序列 [1,1,0,1,1]，cummin 后变成 [1,1,0,0,0]，求和就是2，即连续2天涨停。全部用C实现，Python层零循环。

效果：3000只股票数板从5秒降到0.1秒，提速50倍。

五、回测提速：粗筛 + 精算
如果每天对全池3000只拉10天矩阵，有34000行，耗时约2秒。回测里每天2秒太奢侈。

优化方法：先粗筛昨日涨停股，只对它们拉矩阵。

python
# 步骤1：粗筛（只拉2天数据）
df = get_price(pool, end_date=date, count=2, 
               fields=['close','high','high_limit'], panel=False)
latest = df.sort_values('date').groupby('code').last()
mask = (latest['close'] == latest['high_limit']) | \
       (latest['high'] == latest['high_limit'])
hl_list = list(latest[mask].index)   # 约50-80只

# 步骤2：精算（只对涨停股拉10天矩阵）
matrix = get_limit_matrix(hl_list, date, days=10)   # 500-800行
矩阵从34000行降到600行，耗时从2秒降到0.05秒。

六、修复两个大坑
坑1：炸板永远0
粗筛时如果只筛 close == high_limit，炸板股（盘中触及涨停但收盘未涨停）会被过滤掉，导致 is_za 永远0。

修复：粗筛条件加上 high == high_limit。

坑2：日期显示 1970
用 pd.to_datetime 处理某些类型的时间戳会出错，显示成1970-01-01。

修复：直接 df['date'] = df['date'].astype(str).str[:10]，简单粗暴但有效。
